# 真人模型训练与平台接入说明

本功能在本机处理数据。模型估计采集协议中与探针回答相关的“当前任务专注 / 内部走神”状态，不代表绝对专注能力、诊断或强化训练疗效。

## 操作流程

1. 在独立采集器中按预定名单设置匿名编号及 `development`（开发）/ `test`（封存测试）分组。同一个人的首访、复测始终属于同一组。选择短版研究协议（18～20 分钟，15 个正式探针）或完整研究协议（45～50 分钟，32 个正式探针），完成后停止并导出。两种协议各有 1 个练习探针。
2. 双击套件中的 Studio 程序或启动脚本，在自动打开的平台进入“设置与管理 → 模型管理”。直接访问可使用 `http://127.0.0.1:8765/#/models`，端口以启动提示为准。
3. 选择单个导出目录、包含多个导出的父目录，或采集器合并的数据集目录；也可以在“本机采集目录”输入框直接粘贴绝对路径。先点“导入并验收”核对人数、标签和排除原因，或直接点“一键训练与独立评估”。
4. 等待后台完成。刷新页面不会丢失数据或任务。可以在浏览器内预览报告，也可下载完整成果 ZIP、模型 JSON、独立测试 HTML 报告、评估 JSON 或逐探针预测 CSV。
5. 点“启用此模型（新会话）”。实时监测页将单独展示模型结果、暂停原因及主要特征贡献。运行中的会话继续使用启动时版本。

仿真训练单独放在折叠区域，仅用于链路自检，不覆盖真人模型。原有频带比值指数、预警和神经反馈目标保留原有含义；真人模型概率单独展示和保存。

## 导入数据

- 推荐完整采集导出目录：`manifest.json`、`export.json`、`features.csv`，并保留 `SHA256.json`。
- 合并数据集需要 `dataset.json`、`development.csv`、`test.csv`、`excluded.csv`。新版合并清单附有引擎、设备、单位和 CSV 校验值。
- 旧导出和旧合并数据集可用于离线训练评估。实时加载需要可核对的设备、单位、特征引擎和特征计算实现指纹。旧导出缺少实现指纹时，在本版采集器选择「导出已有记录」，从原始记录重新导出，再导入 Studio。
- 预试数据导入后显示预试人数、非练习探针数、其中可提取脑电特征数和有效二分类回答数。预试数据不进入开发或独立测试。训练条件不足时，验收页显示具体原因。
- 本版 Studio 在导入页和独立测试报告显示各研究协议的采集次数。模型 JSON 的 `training_protocols` 记录实际贡献开发样本的协议编号。短版使用 `attention-validation-short-v1`，完整版本使用 `attention-validation-v1`。
- `recording.sqlite3` 原始采集目录需要先在采集器导出。浏览器只读取特征及清单，不加载、上传整份原始脑电。
- 不要用 Excel 另存后覆盖 CSV；校验值和配套清单不一致时会拒绝导入。请从原记录重新导出。
- 单次最多12 MiB特征文本、50000条探针、3000个配套文件。

仅正式协议完成、真实来源声明、非练习、有有效基线和足够合格脑电、标签明确的样本进入训练或测试。仿真、快速演示、练习、模糊/缺失回答和未完成记录保留在排除集合。来源声明及校验值不能证明实验确实由真人完成，仍需核查实验实施情况。

## 样本、标签与特征

一个探针对应一条样本，不把相邻、重叠窗口当作独立样本。

| 探针回答 | 标签 |
|---|---|
| 1：当前任务 | 0：on_task |
| 3 / 5：个人事务、无关幻想等内部走神 | 1：internal_mind_wandering |
| 其他、超时、取消 | 不进入主要二分类训练 |

使用 θ、α、β 相对功率和三个对数功率比值，共六个特征。取探针出现前12～2秒完全落入该区间的合格窗口平均值：4秒窗、2秒步长、最多6秒历史调理上下文；至少3个合格窗口、覆盖至少6秒、窗口合格比例至少60%，且不能跨任务阶段。

真人模型标签1是“内部走神”，旧仿真模型标签1是“专注”。两者模型文件和规格独立，加载时检查标签方向。

## 训练与独立测试

- 至少5位有效开发组参与者，进行按参与者分组的五折交叉验证；所有到访留在同一折。
- 第一版使用 L2 逻辑回归，比较正则强度0.001、0.01、0.1。每折标准化仅拟合该折训练数据。训练时平衡参与者贡献，再平衡类别。
- 用开发组折外预测选择模型、拟合 sigmoid 概率校准并选择判定阈值。开发组成绩参与这些选择，不是独立测试成绩。
- 在全部开发数据拟合最终模型，先保存模型、折分和冻结记录，再评估测试组。测试组不更新参数、标准化或阈值。
- 主要结果：每类至少5个有效标签的测试参与者的等权平均 AUROC；按参与者重采样2000次计算95%置信区间。与原指数的 `1-focus` 配对比较，原指数判定点保留 `focus<0.4`。
- 同时报告合并样本 AUROC、AP、灵敏度、特异度、平衡准确率、混淆矩阵、校准检查和数据覆盖。只有一种标签时相关指标显示不可计算。
- 主要分析不足20位测试者时明确标为探索性结果。AUC≥0.70、置信区间下界>0.60、有效二分类标签下脑电覆盖≥70%只是内部研发目标，不是赛题或临床标准。
- 同一研究数据目录中，人员分组固定；重复点击相同数据集复用既有任务。测试打开后，新的开发轮次需要新的测试参与者。不同研究请使用独立 Studio 数据目录。

首轮可沿用“8人试采不纳入正式指标、30人开发、30人封存测试”。实际证据强度取决于有效人数、标签和置信区间。

## 实时推理

模型包保存特征顺序、标准化、权重、校准、阈值、标签、训练参与者、设备和单位、引擎及计算实现指纹。只加载受限 JSON，不加载 pickle 或任意代码。

新会话核对设备名称、source_id、通道、标签、采样率和单位。已声明单位与缩放比例冲突时暂停输出；未声明时沿用采集时操作员确认的比例。电极参考仍需操作者核对。

Capture 0.3.1 可在设备信息中记录分包时间处理策略。Studio 0.1.5 导入后将其保留在模型设备信息中，实时特征使用同一有界处理：单点修正不超过50毫秒，较大源时间间断、时钟重置和采样率异常仍拒评。不同时间策略对应的同名设备信息有歧义时暂停加载。原始采样值及源时间戳不改写；逐窗调整量见采集导出的 windows.csv。

模型使用原始缓冲，与采集导出共享历史调理及时间聚合函数。模型会话时间戳仅做时钟校正，不去抖或强制单调，以便排除时间异常。匹配设备的物理幅度比例同步应用于会话基线，模型快照始终保持原始幅度。

每次估计对应当前时刻前12～2秒。信号不新鲜、基线无效、覆盖不足或设备/版本不匹配时暂停输出。目前只在 SART 探针语境下评估；其他阶段显示适用范围提示。相关频带特征的贡献是统计解释，不代表因果机制。

## 成果文件

完整 ZIP 包含：`attention_model.json`、`training_config.json`、`splits.json`、`cv_results.json`、`freeze.json`、`evaluation.json`、`report.html`、`report.md`、`test_predictions.csv`、`MODEL_CARD.md`、`SHA256.json`。

成果包不含原始脑电，原始记录应单独保管。启用模型后的平台会话另保存模型快照和 `attention_predictions.json`，可以追溯版本及各阶段结果。

## 命令行复现

打包程序：

```powershell
.\NingsiStudio.exe train-real --input "D:\实验\采集导出" --output "D:\实验\训练成果_v1"
```

源码：

```powershell
$env:PYTHONPATH='D:\ningsi\ningsi-studio\src;D:\ningsi\ningsi\src'
D:\ningsi\.venv\Scripts\python.exe -m ningsi_studio train-real --input "D:\实验\采集导出" --output "D:\实验\训练成果_v1"
```

`--input`可以重复指定；输出目录必须是新目录，不覆盖旧成果。CLI提供可复现训练评估；平台另提供人员分组及测试使用记录，正式工作建议在同一个平台研究目录中管理。

## 验收边界

测试使用人为构造的软件夹具及模拟信号，只验证实现、数据隔离、特征一致性和导出链路，不能作为真人准确率结果。当前未验证新模型的真人硬件表现、跨设备泛化或强化训练疗效。
## BioMulti 原生 REC 双录

Studio 0.1.6 可导入采集器 0.3.2 的双录特征，用于按受试者分组的初步训练和独立评估。双录模型保留 `biomulti-rec-device-clock-v1` 来源。该时钟来自停止录制后逐包核对的设备数据，普通实时 LSL 输入无法提供它，在线推理会报告 `native_rec_clock_required`。输入单位待确认、时钟未匹配或预试的记录不能提供合格训练行。
