# 双通道额部眨眼控制

本次改动优化实时信号进入评分前的处理与资格判定。它使用个人眨眼校准和两个 EEG 通道的交叉证据，不能保证恢复眨眼期间的真实脑电，也没有重新训练或证明专注度模型的准确率。

## 使用流程

1. 在 Studio 选择当前参与者和实际 EEG 来源，确认通道顺序、原始单位与倍率；保持电极与参考位置一致。
2. 在开始评估页展开“减少眨眼干扰（双通道个人校准）”，点“开始个人眨眼校准”。每次自然短眨眼后等约 0.8 秒，再点“已眨眼，记录这一次”。建议记录 15–20 次，间隔至少 3 秒，避免移动、皱眉和触碰电极。单次标记不通过时按提示补录，已经通过筛查的标记会保留。
3. 校准通过后仍需原来的睁眼基线与信号质检。闭眼静息不被当作噪声模板，也不被标记为“不专注”。
4. 正常评估中，可信的短眨眼按各自通道模板局部拟合；未完成或不可信的事件暂停新评分。信号恢复且质量合格后继续。
5. 校准用于随后启动的本次会话，草稿最长保留 30 分钟，采集需在 120 秒内完成。换人、重新佩戴、改变电极／参考位置或通道与单位配置后重新校准。不能复用另一人的模板。

校准不足时保留信号筛查，不能凭两个通道同时出现波动就自动学习“眼电”。本功能要求两路原始波形，不适用于只有厂商频段功率或专注度数值的来源。设备手册中的 FP1/FP2 CSV 列不能代替对当前 LSL 通道映射与参考电极的实际确认，见[设备说明](BSENSE_R_DEVICE_GUIDE.md)。

## 算法与评分规则

引擎实现位于 `ningsi/src/ningsi/signal/blinks.py`，版本为 `dual-frontal-blink-v1`。输入为已换算为 µV 的两路原始波形；输入与原始存储保持独立，处理函数返回新的波形和质量证据。

- 每次标记单独筛查最近 2.5 秒的双通道波形和可用时间戳。样点不足、时标间断或候选波形异常会拒绝本次标记。生成模板须至少 8 个通过形状和信噪比比较的独立事件，以及累计至少 4 秒通过筛查的背景数据。
- 分别估计两路形状、幅度、背景波动及幅度比范围。检测与拟合联合检查时间、形状、宽度和双通道关系；不会从一路 EEG 中直接减去另一路 EEG。
- 只在已匹配事件附近扣除该通道自己的模板；未发生校正的样点保持原值。模板扣除后仍做残留、幅度、接触、肌电和常规频谱质量检查。
- 无校准、个人配置不匹配、事件落在窗边缘、饱和／非有限值、接触阶跃、持续平台、异常双通道关系或密集重叠事件，均不凭校正结果自动放行。
- 保留“干净”“已校正”“被拒绝”证据。坏窗使专注度结果缺失；不能转成低分，也不能把旧分数当作当前新测量。

这是完整历史窗上的事件处理。单个事件拟合需峰后最多约 0.58 秒已接收数据；窗边缘不外推。当前 Studio `acq-condition-v1` 在已接收上下文内使用正反向滤波，这不等于逐样点因果、零延迟算法。整体延迟还包括取窗、评分步长和传输，未以合成测试推断真机延迟。

已训练的真人模型继续使用其冻结的特征与预处理契约。额外的实时双通道筛查只决定是否允许输出新预测，不把个人模板校正后的波形悄悄替换为旧模型输入。若要用校正波形训练分类模型，需要单独版本化预处理、重新导出训练集并独立验证。

## 验证与限制

在仓库根目录运行：

```powershell
.\.venv\Scripts\python.exe scripts\validate_blink_control.py
```

结果写入 `var/blink-control-20261117/metrics.json` 和 `RESULTS.md`。默认运行 100 组独立合成混合，脑电种子从 50000 开始、眨眼参数种子为 733219，校准数据与测试数据使用不同脑电相位和噪声。早期开发组发现模板中的神经节律残留会使专注指数误差变大，据此加入固定 65 ms 高斯平滑。默认评估组在该参数确定后运行，没有据此继续调参。测试包含幅度／宽度／双通道比例变化、真实产品滤波链、已知干净 θ/α/β 振荡、接触阶跃、平台、饱和、非有限值、窗边缘和密集眨眼。

最终工程验证结果：

| 项目 | 合成数据结果 |
|---|---|
| 干净片段改写／误门控 | 0/100；θ、α、β 功率保持原值 |
| 可信局部校正 | 96/100，另外 4 组保守屏蔽 |
| DC／高通／陷波／低通后的波形 RMSE | 19.209 → 2.944 µV，均值下降约 84.7% |
| 专注 log(β/θ) 绝对误差 | 均值 0.011072 → 0.008805；P95 0.038169 → 0.024077；中位数 0.004342 → 0.006023 |
| 实际 Studio 代码链可评分窗 | 40 组中，未校准 0；校准后 39；干净对照 40 |
| 校准后可评分窗专注分数相对干净真值的绝对偏差 | 0–1 尺度，均值 0.01056，P95 0.02871，最大 0.03129 |

以上校正比例不是临床或真人数据的检测精确率／召回率。专注指数误差的均值和高分位降低，但中位数增加，不能宣称每次眨眼后都更准确。

波形误差下降、可用覆盖提高、频带与专注指数保持是分别评估的量。不能仅凭波形更平滑或 RMSE 更小宣称专注度稳定性提高；详细结果也会报告指数误差恶化的情况。这里的合成信号具有已知真值，但真实脑电在眨眼时没有这种可直接观察的真值。

真实设备验证还需要独立眼电或视频／人工事件标注，并将校准与后续验证分开。至少比较事件精确率与召回率、有效数据比例、未眨眼片段的 θ/α/β 功率偏移、原先与优化后专注指数变化，以及受试者外模型表现。没有这些数据前，本次交付只证明软件规则与合成场景行为。

## 2026-11-18 历史真人记录回放

已按用户确认的“只有正常测试、没有专门眨眼校准”情况，回放 7 份本机真实设备记录，合计 1,186,290 个双通道采样点，约 79.09 分钟。相同 Studio 滤波和质检条件下，新增无校准眨眼筛查使合格窗从 139/2363 降到 99/2363；额外叠加时标检查后为 113→83。窗口长 4 秒、步长 2 秒，不能把窗口数乘 4 当作有效时长。

新增拒绝的 40 窗中，34 窗触发原始信号相对中位数偏移超过 1000 µV 的规则，3 窗是边缘事件，3 窗是未校准候选。这不是 40 次经独立确认的眨眼；也没有独立真值证明每一窗都应被拒绝。原始频谱存在明显 50 Hz 集中、幅度变化和时标异常，问题超出眨眼范围。

本次没有已标记的个人眨眼模板，因此两条路径的波形完全相同，校正窗为 0，没有生成新专注分数或训练样本。仅用各记录前至多 120 秒的自动候选进行的探索性拟合均未通过原校准门槛；未放宽阈值、拼接片段或借用他人模板。这也不表示整份记录中没有可用的眨眼片段。

结论是现有数据只能证明新增质量门控的行为，尚未证明真人眨眼校正收益。原始输入 SHA-256 在处理前后均一致。复现脚本为 `scripts/replay_real_blink_control.py`，详细逐窗证据和本机图形报告位于 `var/blink-real-replay-20261118/`。已有发行包不因本次离线分析自动更新。

在仓库根目录运行以下命令，将示例路径换成含 `manifest.json` 的双通道录制或导出目录。可重复使用 `--recording` 添加其他录波，并为本次输出指定新目录。

```powershell
python scripts/replay_real_blink_control.py --recording rest "D:\EEG\example-rest" --output var/blink-replay-example
```

批量回放可使用 `--sources recordings.json`。文件内容形如 `{"rest":"recordings/rest","task":"recordings/task"}`，相对路径从清单所在目录解析。省略输入参数时，程序会读取本机的 `var/blink-replay-sources.local.json`。

## 方法依据

[MNE 官方 ICA 伪迹教程](https://mne.tools/stable/auto_tutorials/preprocessing/40_artifact_correction_ica.html)提醒，额部 EEG 代理眼电包含真实脑活动。双通道与个人模板能提供判断依据，不能把共同信号直接视为纯眼电或保证源分离。本实现采用局部事件处理与保守门控，没有把双通道普通 ICA 作为默认去眨眼方法。
